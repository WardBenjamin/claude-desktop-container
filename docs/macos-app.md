# The macOS app: Claude Black.app

`/Applications/Claude Black.app` is the xpra macOS client (Xpra-Light),
re-badged with its own identity, icon, and a launcher that boots the whole stack.
It is assembled by `build-app.sh`, which is fully re-runnable.

## Build / rebuild / install

```sh
~/VM_Workspace/_host/build-app.sh
```

One command does everything: download, patch, icon, identity, launcher, sign,
install. Re-running it rebuilds `/Applications/Claude Black.app` from scratch
(it removes and recreates the bundle). Requires the Xcode Command Line Tools
(`clang`) for the launcher stub — `xcode-select --install` if missing.

## What the build does, in order

1. **Download the client.** Fetches `Xpra-Light-arm64-6.5.4-r2.dmg` from
   xpra.org, mounts it read-only, and copies `Xpra-Light.app` to
   `/Applications/Claude Black.app`. (The dmg also contains an empty `Xpra.app`
   template — ignore it; the real app is `Xpra-Light.app`.)
   - **arm64 only.** xpra.org publishes only the "Light" flavor for arm64, which
     omits the video codec bundle that is not needed on a local link. On an Intel
     Mac, change `DMG` to the `x86_64` build.
   - **Homebrew will not help.** The `xpra` cask is disabled in Homebrew because
     the app fails Gatekeeper (unsigned/not notarized), so the dmg is fetched
     directly. Gatekeeper is cleared with `xattr -dr com.apple.quarantine`.

2. **Icon from the committed asset.** Uses `assets/claude-black.png`, an original
   greyscale "wiggly burst" mark generated by `tools/make-logo.py` (pure stdlib
   Python, no external renderer). `sips` builds a full iconset (16–512 plus @2x),
   `iconutil` produces `ClaudeBlack.icns`, and the same PNG replaces the two
   runtime icons xpra loads for the Dock/window (`share/icons/xpra.png`,
   `share/xpra/icons/xpra.png`). No dependency on Anthropic's installed app.
   To change the logo, edit the constants in `tools/make-logo.py`, run
   `python3 tools/make-logo.py assets/claude-black.png`, and rebuild.

3. **Bundle identity.** Via `PlistBuddy`, sets `CFBundleName`,
   `CFBundleDisplayName` = "Claude Black", `CFBundleIdentifier` =
   `com.blward.claude-black`, `CFBundleIconFile` = `ClaudeBlack.icns`,
   `CFBundleExecutable` = `ClaudeBlack`.

4. **Client patches** (two `sed` edits to the bundled Python — see below).

5. **Launcher script** `Contents/MacOS/ClaudeBlack.sh` (see below).

6. **Mach-O stub** `Contents/MacOS/ClaudeBlack`. launchd refuses to spawn a
   bundle whose `CFBundleExecutable` is a shell script ("Launchd job spawn
   failed", POSIX 162). So the real executable is a tiny C program that resolves
   its own path and `execv`s `/bin/zsh` on `ClaudeBlack.sh` beside it, passing
   through any args. Compiled with `clang -O2`.

7. **Sign and clean up.** Ad-hoc signs the bundle (`codesign --force --deep
   --sign -`), removes the stale `xpra.icns`, points the document-type icon key
   at `ClaudeBlack.icns`, and removes the superseded plain `Xpra-Light.app` if
   nothing is running from it.

## Client patches applied to the bundle

### Decoration (title bar for resize affordance)
```
# client/gtk3/window/base.py
return metadata.boolget("decorations", True)   ->   return True
```
Electron reports its frameless window as undecorated; the client would then make
a borderless NSWindow with only a finicky invisible drag border. Forcing
decoration gives a native title bar. (Note: resize still does not actually work —
see `xpra-findings.md` — so this mainly provides a move handle and fullscreen
button, at the cost of a thin second bar above Electron's own header.)

### Drop size-constraint hints
```
# client/gtk3/window/window.py, in apply_geometry_hints()
# strips min_width/min_height/max_width/max_height/width_inc/height_inc/base_width/base_height
```
Electron forwards a minimum-size hint; a GTK-on-Quartz window with that
constraint rejects AppKit tiling resize. Stripping the hints makes the window
report as freely resizable. (Did not fix tiling in practice; kept because it is
harmless and removes a real constraint.)

## The launcher: `ClaudeBlack.sh`

Run by the stub. Steps:

1. **PATH** is set to include `/usr/local/bin` and `/opt/homebrew/bin` because
   GUI launches get a minimal PATH and `docker` lives in `/usr/local/bin`.
2. **OrbStack:** if `docker info` fails, `open -gja OrbStack` and wait up to 90 s.
3. **Container:** `docker compose -f ~/VM_Workspace/_host/compose.yaml up -d`,
   then wait for port 14500.
4. **Center the window** (backgrounded): uses a JXA (`osascript -l JavaScript`)
   snippet that imports **CoreGraphics** (not AppKit — importing AppKit makes the
   helper register as a *second Dock icon*) to read the primary display bounds,
   and System Events Accessibility to set the window position. First run prompts
   once to allow "Claude Black" to control System Events.
5. **Attach:**
   ```
   Xpra-Light attach tcp://localhost:14500 \
     --opengl=force --desktop-scaling=0.5 --system-tray=no \
     --encodings=rgb,png --title="Claude Black"
   ```

### Attach flags and why

| Flag | Reason |
|------|--------|
| `--opengl=force` | GL backing presents at Retina scale. Plain `--opengl=yes` skips menus/tooltips (`NO_OPENGL_WINDOW_TYPES`) and renders them soft via Cairo. `force` bypasses that list. |
| `--desktop-scaling=0.5` | Downscales the 2x Electron render back to logical points so text is crisp and the window is the right size. See `xpra-findings.md` for the full trade-off. |
| `--system-tray=no` | macOS 26 AppKit crashes (SIGSEGV in `+[NSStatusBar systemStatusBar]`) tearing down xpra's forwarded menu-bar status item on disconnect. Not forwarding the tray removes the crash. |
| `--encodings=rgb,png` | Lossless only. On a local link there is no bandwidth reason to allow WebP/video, which mishandled popup alpha (grey halos) and produced magenta flashes. |
| `--title="Claude Black"` | Window title. |

## Updating the xpra client version

Change `DMG` in `build-app.sh` to a newer `Xpra-Light-arm64-<ver>.dmg` from
`https://xpra.org/dists/MacOS/arm64/`. Keep the **client major version matching
the container's xpra-server major version** (the Dockerfile installs whatever the
xpra.org Debian repo currently serves; check with
`docker compose exec claude xpra --version`). When a new version lands the HiDPI
coordinate fix (see `xpra-findings.md`), retest with the scaling flags removed.

## Re-signing after manual edits

If you hand-edit anything inside the bundle (e.g. test a client patch), re-sign:
```
codesign --force --deep --sign - "/Applications/Claude Black.app"
codesign --verify --deep --strict "/Applications/Claude Black.app"
```
Ad-hoc signing (`-`) is sufficient for local use; the app is not notarized.
